# UI Mockups & Layouts

Use this recipe for any request to mock up, wireframe, design, or preview a screen, dashboard, component, or app flow — including curriculum studio screens, etextbook layouts, music app views, and IDE-style tools.

## Prompt scaffold

1. **Subject line** — "Editorial UI mockup of a [product type] screen showing [primary content]."
2. **Product context** — what the app does, who uses it, what task this screen supports.
3. **Layout** — explicit panel layout: "left sidebar with [items], center canvas with [content], right inspector panel with [controls], top bar with [actions]."
4. **Primary content** — describe what's actually on the canvas (a lesson tree, a 3D geometry viewer, a notation staff, a knowledge graph).
5. **Components called out** — buttons, tabs, search field, breadcrumb, progress bar, chips. Be specific about which are present.
6. **Type and color system** — "modern editorial sans (Inter / IBM Plex style), 14px body, 24px section titles, neutral warm-gray surface (#F7F5F2), one accent color [hex or name]."
7. **Density** — "Linear/Notion-density, generous whitespace" or "Figma-density information-rich" or "iPad-app touch-friendly."
8. **Framing** — "Full window at 1440×900, browser chrome hidden" or "iPad portrait at 1024×1366" or "isolated component on neutral background."
9. **Style register** — always: "Editorial UI mockup, flat modern interface, crisp pixel rendering, no skeuomorphism, no glass effects unless requested."
10. **Negative cues** — "no lorem ipsum gibberish, no fake placeholder text in dummy languages, no stock-photo avatars, no anachronistic 2010-era UI chrome, no Material-Design defaults, no Bootstrap look."

## Aspect ratio

- Desktop / web app screen → `16:9`
- iPad / tablet portrait → `3:4`
- Phone screen → `9:16`
- Single component / card / inspector panel → `1:1` or `4:3`

## Model

- Default: `gpt_image_2` — best for clean, readable interface text.
- Use `gpt_image_1_5` with `background: "transparent"` only for isolated component cutouts (a single card, a single button group).

## Worked example prompt

```
Editorial UI mockup of a curriculum-authoring desktop app screen called "Lesson Studio."

Product context: an EdTech tool where a curriculum designer assembles K–8 geometry lessons by dragging visual modules (shapes, manipulatives, prompts) into a lesson timeline.

Layout: left sidebar (240px) listing lesson modules grouped by strand (Geometry, Number, Measurement) with small monochrome icons; center canvas showing a horizontal lesson timeline with five sequential cards (Warm-up, Explore, Make, Share, Reflect); right inspector panel (320px) showing properties of the currently selected "Explore" card — title field, learning goal, attached manipulative, estimated minutes; top bar with breadcrumb (Grade 3 › Unit 2 › Lesson 4), Save button, and a Preview button.

Type and color: modern editorial sans similar to Inter, 14px body, 22px section titles, warm neutral surface #F7F5F2, single deep-indigo accent #2A2D7C, subtle 1px dividers.

Density: Linear/Notion-like, generous whitespace, clear focus on the timeline.

Framing: full desktop window at 1440×900, browser chrome hidden.

Style: editorial UI mockup, flat modern interface, crisp pixel rendering, no skeuomorphism, no glass effects.

Negative: no lorem ipsum, no stock avatars, no Material-Design defaults, no anachronistic chrome.
```

Aspect ratio: `16:9`. Model: `gpt_image_2`. Filename: `ui_lesson_studio_timeline_v1`.

## Common follow-ups to offer

- A dark-mode variant.
- A mobile/tablet companion view of the same screen.
- A component close-up of the inspector panel.
- An empty-state version of the same screen.
