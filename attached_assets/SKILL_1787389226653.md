# Detailed Visuals

This skill is the single entry point for producing **real raster images** in this workspace. It exists because the designer works on geometry-driven curriculum, Atlas-style civilization research, and EdTech UI — all of which require *seeing* artifacts, scenes, patterns, and screens, not reading descriptions of them.

## When to Use This Skill

Load and follow this skill whenever the user asks for any of:

- A visual, image, picture, render, illustration, drawing, sketch, painting, photo, or reference
- A mockup, wireframe, UI, layout, screen, dashboard, or component preview
- A pattern, motif, ornament, tile, textile, or iconography sample
- A statue, figurine, sculpture, relief, mask, vessel, or piece of jewelry
- An architectural view (temple, ziggurat, courtyard, gate, plan, elevation)
- A scene of ritual, daily life, myth, deity, or creature from a specific civilization
- "Show me…", "what would X look like…", "mock up…", "draw…", "render…", "depict…"

Treat ambiguous visual requests (e.g. "I need a reference for Inanna") as a trigger. Generate the image first; ask follow-up refinement questions only after delivering version 1.

## Hard Rules

1. **Never use ASCII art, box-drawing characters, or SVG/HTML drawings as a substitute** for a visual. If the user wants to see something, they want a raster image.
2. **Always call `asi-generate-image`** via the `media` skill's CLI. If `media` is not already loaded in the session, load it first.
3. **Never describe what an image would look like instead of generating it.** If a visual is requested, the visual must be produced.
4. **Always share the file.** After generation, call `share_file` with a clean `name` (e.g. `inanna_relief`, `ziggurat_ur_dawn`) so the user actually sees it.
5. **For batches**, generate images in parallel by issuing multiple `bash` calls in one tool block. Do not serialize unless images depend on each other.

## Workflow

### 1. Classify the request

Pick the category that best matches the ask. Each maps to a recipe in `references/`:

| Category | Recipe file | Typical aspect | Default model |
|---|---|---|---|
| UI mockups / layouts / screens | `references/ui-mockups.md` | `16:9` or `9:16` | `gpt_image_2` |
| Geometric patterns / motifs / textiles / tile | `references/geometry-art.md` | `1:1` | `gpt_image_2` |
| Iconography / glyphs / single symbol studies | `references/geometry-art.md` | `1:1` | `gpt_image_2` |
| Architecture (temples, ziggurats, plans, elevations) | `references/architecture.md` | `16:9` or `4:3` | `gpt_image_2` |
| Figurines / sculpture / statues / reliefs / masks | `references/artifacts.md` | `3:4` | `gpt_image_2` |
| Jewelry / small metal / inlay / cylinder seals | `references/artifacts.md` | `1:1` or `4:3` | `gpt_image_2` |
| Ultra-realistic historical scenes (daily life, ritual, market, court) | `references/scenes.md` | `16:9` | `gpt_image_2` |
| Mythological gods, demons, hybrid creatures | `references/mythology.md` | `3:4` (figure) or `16:9` (scene) | `gpt_image_2` |
| Music notation, instruments, performance, fretboards, modal/maqam diagrams | `references/music-notation.md` | `16:9` (notation) / `3:4` (instrument) | `gpt_image_2` |
| Manuscripts, clay tablets, codices, scrolls, ostraca, inscribed stelae | `references/manuscripts.md` | `4:3` or `3:4` (page) / `1:1` (tablet) | `gpt_image_2` |
| Cosmograms, mandalas, yantras, world maps, knowledge diagrams | `references/cosmology-diagrams.md` | `1:1` (radial) / `3:4` (axial) | `gpt_image_2` |

If the request spans several categories (e.g. "a ritual scene that shows the jewelry up close," or "a scribe at work *and* a study image of the tablet he's writing on"), generate **two images**: one wide scene, one close-up study. Recipe files cross-reference each other for these handoffs.

### 2. Read the matching recipe file

Open the relevant file under `references/` and follow its prompt scaffold. Each recipe defines the structural prompt blocks the image needs (subject, civilization specificity, material, lighting, framing, style, negative cues). Do **not** improvise a one-line prompt — the visuals the designer needs only work with layered, specific prompts.

### 3. Compose the prompt

Every prompt must include, in order:

1. **Subject line** — the one-sentence "what is this" statement.
2. **Civilization / period / region specificity** when relevant (e.g. "Early Dynastic III Sumerian, c. 2600 BCE, Ur"). Vague historical prompts produce generic fantasy output.
3. **Material and craft** (carved alabaster, fired clay, lapis-and-gold inlay, woven wool, polished diorite, hammered electrum). Material drives realism more than any other single cue.
4. **Composition and framing** (three-quarter view, frontal elevation, overhead plan, eye-level wide shot, macro close-up).
5. **Lighting** (low-angle dawn through clerestory, oil-lamp warm interior, raking sidelight emphasizing tool marks, overcast museum studio light).
   - For notation, manuscripts, and cosmograms, also specify the **notation/script system** and the **medium being emulated** (e.g. "Arabic maqam scroll notation with quarter-tone accidentals," "naskh Arabic on vellum," "incised cuneiform clay tablet"). Never let the model invent a script — and never expect readable text from any image model.
6. **Style register** — pick exactly one:
   - "Ultra-realistic photographic, museum-quality reference"
   - "Documentary archaeological photograph"
   - "Architectural rendering, photoreal materials"
   - "Editorial UI mockup, flat modern interface, no skeuomorphism"
   - "Studio product photograph on neutral seamless background"
   - "Painterly historical reconstruction in the style of museum dioramas"
7. **Negative cues** when needed: "no text, no captions, no watermark, no logos, no modern objects, no costume jewelry, no fantasy embellishment, no anachronisms."

### 4. Pick aspect ratio and model

- Default model: `gpt_image_2`.
- Use `nano_banana_pro` only when the user explicitly wants fast concept iteration.
- Use `gpt_image_1_5` with `background: "transparent"` when the output is a cutout asset (icon, single figurine on transparent bg, UI sticker).
- Aspect ratio: follow the table in step 1. Override only if the user specifies.

### 5. Generate (and share)

Issue the `asi-generate-image` call via `bash` with `api_credentials: ["llm-api:image"]`. Use descriptive filenames in `snake_case` that encode subject and view, e.g.:

- `ui_lesson_builder_dashboard_v1`
- `sumerian_lyre_of_ur_studio_v1`
- `inanna_descent_underworld_scene_v1`
- `pythagorean_tile_pattern_v1`

After generation, **always** call `share_file` with the absolute path and a stable `name` (without the `_v1` suffix) so subsequent revisions become versions of the same asset.

### 6. Offer one refinement

After delivering the image, offer a single concrete next move: "Want a tighter close-up of the headdress, a side-elevation companion, or a different material variant (basalt vs. alabaster)?" Do not ask open-ended "what do you think" questions.

## Batch Requests

When the user asks for "a set of…", "options for…", "variants…", or "a sheet of…":

- Generate **3–4** images by default.
- Vary one axis at a time (e.g. material, period, view angle, lighting) and name files accordingly: `..._alabaster_v1`, `..._basalt_v1`, `..._terracotta_v1`.
- Issue all generation calls in a single tool block so they run in parallel.
- Share each file individually with a clear `name`.

## Anti-Patterns (do not do)

- Returning an ASCII or text mockup of a UI when a mockup is asked for.
- Returning an SVG/HTML drawing of a pattern, deity, or artifact.
- Writing "I cannot show images" — this workspace can. Generate one.
- One-line prompts like `"a Sumerian statue"` — always use the layered prompt scaffold.
- Mixing civilizations or periods unless the user explicitly asks for a fusion.
- Adding modern objects, lens flares, or "epic fantasy" cues to historical reconstructions.
- Forgetting to call `share_file` after generation.

## Quick Reference: Minimal Call

```bash
asi-generate-image '{
  "prompt": "<layered prompt from step 3>",
  "filename": "<snake_case_subject_view_v1>",
  "aspect_ratio": "<from table>",
  "model": "gpt_image_2"
}'
```
with `api_credentials: ["llm-api:image"]`, followed by `share_file` on the resulting PNG.

For full prompt scaffolds per category, read the matching file in `references/`.
